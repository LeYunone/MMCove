# 接口文档 - 知识库 MCP Server 接入

| 项 | 内容 |
|---|---|
| 文档版本 | 1.1 |
| 发布日期 | 2026-09-07 |
| 服务方 | MMCove（mmcove-agent 平台） |
| 对接方 | 开发者（Claude Code / Cursor 等 AI 编码工具） |
| 协议 | MCP（Model Context Protocol）SSE 传输 |
| 端点 | `http://<host>:8808/sse`（消息端点 `/mcp/message`） |

---

## 1. 概述

知识库产品线体系提供「**产品线 → 知识库 → 文档**」三级组织:

- **产品线**（product_line）:内各产品线的顶层目录,互相隔离;
- **知识库**（knowledge_base）:挂产品线,绑定 Embedding 渠道与 Milvus collection;
- **文档**（knowledge_document）:md/txt/pdf/docx 入库,切片向量化供语义检索。

外部 AI 工具通过**标准 MCP 协议**接入,获得知识库的目录浏览、语义检索、文档上传能力;
**删除类操作不进 MCP**,只能走管理界面（/admin/knowledge-bases）,防止 AI 误删。

### 1.1 架构

```
Claude Code / Cursor                MMCove 服务
┌──────────────────────┐   SSE   ┌────────────────────────────────┐
│ MCP 客户端            │ ──────► │ /sse + /mcp/message             │
│ Authorization: sk-xx │         │  鉴权 + X-Product-Line 解析      │
│ X-Product-Line: 物联  │         │  → 默认产品线(会话身份桥)         │
└──────────────────────┘         │  → KbAccessService 隔离策略      │
                                 │  → 5 个知识库 MCP 工具            │
                                 │  → Milvus + MySQL               │
                                 └────────────────────────────────┘
```

### 1.2 交互模型（重要）

调用方身份 = **MCP 客户端配置时自报的产品线**（`X-Product-Line` 请求头,各自填自己的产品线名称或编码）+
API Token 鉴权。**全程使用产品线名称,不接触数字 ID**:

| 场景 | 行为 |
|---|---|
| 平时使用（没提产品线） | 查询/目录/上传等一切行为默认用**配置的产品线** |
| 话术带产品线（如"查物联产品线的资料"） | 查询范围 = **指定产品线 + 默认产品线**两线知识库 + 共享库**合并** |
| 上传到默认产品线的库 | 直接执行 |
| 上传到话术指定的其他产品线的库 | **先询问确认**:AI 会向你确认,你确认后才上传 |
| 上传到其他未提及的产品线 / 别人线的私有库 | 拒绝 |
| 未配置 X-Product-Line 且 token 未绑线 | 仅可读共享库,不可上传 |
| 删除 | 不提供（走管理界面） |

共享库（is_shared=1）始终在可读范围内。

## 2. 接入方式

### 2.1 前置条件

1. 向管理员申请 API Token（`sk-` 开头）;
2. 确认自己的产品线名称（问管理员或看管理后台「产品线管理」页）;
3. 服务地址（dev）: `http://<your-host>:8808`（按实际部署替换 host:port）。

### 2.2 Claude Code 接入

命令行添加:

```bash
claude mcp add --transport sse mmcove-knowledge http://<your-host>:8808/sse \
  --header "Authorization: Bearer sk-你的token" \
  --header "X-Product-Line: 示例产品线"
```

或项目 `.mcp.json`:

```json
{
  "mcpServers": {
    "mmcove-knowledge": {
      "type": "sse",
      "url": "http://<your-host>:8808/sse",
      "headers": {
        "Authorization": "Bearer sk-你的token",
        "X-Product-Line": "示例产品线"
      }
    }
  }
}
```

`X-Product-Line` 填**产品线名称**（中文可）或**编码**（如 `iot`,见产品线管理页）。配置错误会在连接时被拒绝并提示原因。

### 2.3 Cursor 接入

Cursor Settings → MCP → Add Server:

```json
{
  "mcpServers": {
    "mmcove-knowledge": {
      "url": "http://<your-host>:8808/sse",
      "headers": {
        "Authorization": "Bearer sk-你的token",
        "X-Product-Line": "示例产品线"
      }
    }
  }
}
```

### 2.4 连通性速测（不依赖客户端）

```bash
# 无 token → 应 401
curl -i http://<your-host>:8808/sse

# 带 token + 产品线 → 返回 SSE 流,首事件 endpoint
curl -N -H "Authorization: Bearer sk-你的token" \
     -H "X-Product-Line: 示例产品线" \
     http://<your-host>:8808/sse
```

## 3. MCP 工具清单

所有工具入参/出参均为中文友好 JSON;错误返回 `{"success":false,"message":"原因"}`,不抛异常栈。

### 3.1 listProductLines

列出全部产品线目录。返回 id/code/name/description/status。不确定产品线叫什么时先调它。

### 3.2 listKnowledgeBases（productLineName 可选）

列出当前可访问的知识库。默认 = 配置的产品线 + 共享库;
用户话术提到产品线时传 `productLineName` → 「指定线 + 默认线 + 共享库」合并结果。
返回 id/name/description/productLineName/isShared/dimensions。

### 3.3 listDocuments（kbId）

列出指定库的文档目录（需可读）。返回 id/title/mime/status（0 待入库 1 已入库 2 失败）/createdAt。

### 3.4 searchKnowledgeBase（query, kbId?, productLineName?, topK?）

**核心工具**。语义检索知识库,返回相关文档切片（按库分组拼接）。

- 默认范围 = 配置的产品线 + 全部共享库;
- 用户话术提到产品线（"查物联产品线的资料"）→ 传 `productLineName`,
  范围 = 「指定线 + 默认线 + 共享库」合并检索;
- 传 `kbId` 单库精确检索;`topK` 每库召回切片数（默认 5,最大 20,总上限 50）。

示例提问:「设备激活失败怎么排查?」「物联产品线里有没有 license 机制的设计文档?」

返回（文本）:

```
以下是知识库检索到的相关内容(问题: xxx),请据此回答用户:

【库: 设备激活手册】
--- 切片 1 ---
...文档内容...
```

### 3.5 uploadDocument（kbId, title, content, contentEncoding?, mime?, productLineName?, confirm?）

上传文档入库（触发切片 → Embedding → Milvus）。「把本次文案/资料/笔记存到知识库」时调用。

| 参数 | 说明 |
|---|---|
| kbId | 目标库 ID |
| title | 文档标题 |
| content | markdown/txt 传原文;pdf/docx 传 base64 |
| contentEncoding | `text`（默认）/ `base64` |
| mime | 可选,默认按标题扩展名推断 |
| productLineName | 用户话术指定的目标产品线（跨线上传时用于确认判断） |
| confirm | 跨产品线上传的用户确认:第一次调用会被要求确认,AI 向用户确认后带 `yes` 重调 |

**上传规则**:目标库属于配置的默认产品线 → 直接执行;
属于话术指定的其他产品线 → 返回确认提示（AI 会向你询问「是否上传到XX产品线」）,
确认后带 `confirm=yes` 重调才执行;其余情况拒绝。

**限制**:解码后 ≤ 4MB;更大文件（≤ 20MB）走管理界面上传。

返回 `{ "success": true, "data": { "docId": 12, "kb": "设备激活手册", "status": 1 } }`。

### 3.6 composeVibePrompt（task, productLineName?）— Vibe 流水线提示词组装

编码任务的入口工具。当用户要求修复 bug/开发新功能/重构/补测试时,外部 AI 在开始编码前调用,
把返回的提示词作为本次任务的执行指令,按阶段顺序逐阶段执行。

- `task`:用户原始任务描述(保留原话与报错细节);
- `productLineName`:可空(用户话术提到的其他产品线)。

返回**纯文本提示词**,包含:runId(执行实例,后续上报/恢复用)、意图结论、产品线背景、
知识锚点(带相关性门槛的 RAG 检索片段)、阶段地图(每阶段角色指令/产出物/门禁)、执行约定。
内置流水线:bug-fix(复现定位→根因→修复→互审→回归→收尾)、feature-dev(需求→方案→计划→实现→互审→验收→文档)。

### 3.7 reportStage（runId, stageCode, status, summary?, artifactTitle?, artifactContent?）

流水线执行过程中上报阶段进度并挂存产物。每个阶段开始/完成时调用:
`status` 传 starting/completed/failed;阶段产出物(分析报告/方案/评审清单/测试报告等文本)
通过 `artifactTitle`+`artifactContent` 上报存档。返回总进度(如 2/6);全部阶段完成时流水线收敛。

### 3.8 getRunContext（runId?）— 上下文恢复(防压缩)

当对话被压缩丢失任务指令/阶段地图,或用户说"继续之前的任务"时调用。
`runId` 可空(自动取当前产品线最近活跃实例)。返回原始执行指令完整快照 + 当前进度
(已完成阶段/产物索引)——从断点继续,不重复已完成阶段。

### 3.9 getPipelineStage（pipelineCode?）

流水线/阶段目录查询,`pipelineCode` 留空返回全部流水线及其阶段清单(门禁/产出物要求)。

> **薄壳 skill**:推荐把 `doc/薄壳skill模板-vibe流水线-20260911.md` 中的两条规则
> 拷进你项目的 CLAUDE.md,让本地 AI 养成"编码任务先 compose、丢上下文即恢复"的习惯。

## 4. Token 申请

1. 管理后台（/admin/tokens）创建/审批 Token（`sk-` 开头）;
2. 产品线身份走 MCP 客户端配置的 `X-Product-Line` 头,无需管理员后台绑定
   （token 绑定产品线仅作为未配 header 时的兜底）;
3. 换产品线 = 改自己 MCP 配置里的 `X-Product-Line` 值即可,无需换 token。

## 5. REST 管理接口（可视化界面用,需平台 JWT）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/product-lines` | 产品线列表/创建（code 唯一且不可改） |
| PUT/DELETE | `/api/product-lines/{id}` | 更新/删除（有挂库时拒绝删除） |
| GET/POST | `/api/knowledge-bases` | 知识库列表/创建（必填 productLineId） |
| PUT/DELETE | `/api/knowledge-bases/{id}` | 更新/删除（删除级联清向量） |
| POST | `/api/knowledge-bases/{id}/documents` | 粘贴文本上传（body=正文） |
| POST | `/api/knowledge-bases/{id}/documents/file` | **文件上传**（multipart,md/txt/pdf/docx,≤20MB） |
| GET/DELETE | `/api/knowledge-bases/{id}/documents[/{docId}]` | 文档列表/删除（删除级联清向量） |
| GET/PUT | `/api/knowledge-bases/agent-bindings/{agentId}` | Agent 关联知识库 |
| GET/POST/PUT/DELETE | `/api/vibe/pipelines[/{id}]` | Vibe 流水线 CRUD(steps 全量替换;删除有绑定/实例守卫) |
| GET/POST | `/api/vibe/pipelines/{id}/export · /pipelines/import` | 流水线 YAML 导入导出(支持 extends 继承) |
| GET/POST/PUT/DELETE | `/api/vibe/stages[/{id}]` | 全局阶段库 CRUD(被引用阶段拒删) |
| GET/PUT | `/api/vibe/product-lines/{id}/pipeline-bindings` | 产品线流水线绑定+阶段覆盖 |
| POST | `/api/vibe/compose-preview` | compose 全链路调试预览(须显式 productLineId) |
| GET | `/api/vibe/runs[/{runCode}]` | 执行实例轨迹分页/详情(含产物) |

## 6. FAQ

| 现象 | 原因与处理 |
|---|---|
| 连接 /sse 返回 401 | token 缺失/禁用/过期,或 `X-Product-Line` 配置的产品线不存在(响应体会说明原因) |
| 检索返回「当前无可检索的知识库」 | 未配 `X-Product-Line` 且 token 未绑产品线且无共享库 |
| 上传报「不在可写范围」 | 目标库既不属于你的默认产品线,也不是话术指定的产品线;在话术中明确目标产品线 |
| 上传时 AI 反问「是否上传到XX产品线」 | 正常的跨线确认机制,回答确认后 AI 会带确认重传 |
| 上传/检索报「429 余额不足(1113)」 | 智谱 embedding-3 资源包耗尽——**部署前置条件**：智谱账户需保持 embedding-3 可用余额 |
| 上传超 4MB 失败 | MCP 通道上限;走管理界面 multipart 上传（20MB） |
| 老文档删除后向量仍在? | 2026-09-07 前入库的存量文档无 vector_id,重新上传一遍即可彻底清理 |
| AI 说「无法删除知识库」 | 设计如此;删除走管理界面,不进 MCP |

## 7. 联调验收清单

| 用例 | 预期 |
|---|---|
| 配置 X-Product-Line=线A,检索仅线A有的关键词 | 命中线A库,不命中线B私有库 |
| 同配置检索共享库关键词 | 共享库内容可见 |
| 问「查线B的资料」(带产品线名称) | 线B + 线A + 共享库合并结果 |
| 说「把这段文案存到知识库」 | AI 存入默认产品线(线A)的指定库 |
| 说「存到线B的知识库」 | AI 先询问确认;确认后才入库线B |
| 说「存到线C的知识库」(未提及且非默认) | 拒绝并说明可写范围 |
| 配置 X-Product-Line=不存在的线 | 连接即被拒,响应说明产品线不存在 |
| 管理界面删除文档后检索 | 该文档内容不再命中（向量已清） |
